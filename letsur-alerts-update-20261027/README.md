# Slack 알림 기능

**긴급으로 분류된 미확인 사건을 Slack으로 알립니다.** 기존 팀원 파일을 건드리지 않은 별도 검토용 사본입니다.

## 1. 어떤 알림을 보내나요?

예정 가격·조건 변경, 할인 종료, 모델 종료, 공급 경로 제거를 알립니다. 같은 사건의 입력·출력 가격 등은 카드 하나로 묶습니다. 카드에는 변경 내용, 남은 날/경과일, **확인함·대시보드 버튼**이 표시됩니다.

## 2. 긴급성은 어떻게 판단하나요?

- **대응기간이 5일 이내**이면 긴급으로 분류합니다. 대응기간은 적용일이나 이용·할인 종료일까지 남은 날입니다.
- 기한이 이미 지났어도 미확인이면 알립니다. 마감 없는 일반 변화는 대시보드에서 확인합니다.
- 기본은 검증된 사건입니다. 공식 출처·대상·일정이 명확하고 허용된 미확정 사유만 있는 일부 사건도 ‘미확정’ 표시로 알립니다. 매출·사용량에 따른 사업 영향은 평가하지 않습니다.

## 3. 알림은 어떻게 만들어지나요?

**수집 → 이벤트 생성과 분류 → GitHub에 결과 저장 → 결과 다운로드 → 긴급성·확인 여부 판단 → 카드로 묶기 → Slack 발송**

수집 예약은 매일 **09:17 KST**입니다. 10분마다 GitHub 자동 실행이 성공했는지 확인해 새 결과를 처리합니다. 현재는 수집 뒤의 배포 단계까지 성공해야 새 결과를 가져옵니다.

## 4. 실제 자료에서는 얼마나 오나요?

10월 26일 자료는 **395개 이벤트 중 4개가 대상 → 3카드 → 1메시지**였습니다. 10월 25일 자료도 발송량이 같았습니다.

입력을 고정한 시뮬레이션에서는 미확인 시 매일 1메시지, 모두 확인한 뒤에는 0메시지였습니다. 현재 양은 적지만 **하루 총량 제한은 없습니다.** 합성 긴급 카드 100개는 9메시지로 나뉩니다. [검증 결과](SIMULATION.md)

## 5. 미확인 알림은 다시 보내나요?

**매일 수집 완료 후 재알림합니다.** 기한이 지나도 유지하며, 한 사람이 ‘확인함’을 누르면 해당 내용의 공용 재알림이 멈춥니다. 읽음·대응 완료를 뜻하지는 않습니다. 가격·일정 등 핵심 내용이 바뀌면 다시 확인 대상이 됩니다.

같은 날 동일 내용은 중복 발송하지 않습니다. 수집이 종일 없으면 23시 이후 기존 건만 재알림합니다. 전송 성공 여부가 불명확한 건은 중복 방지를 위해 보류합니다.
